# Security Policy

## Reporting a Vulnerability

**Please do not open a public GitHub issue for security vulnerabilities.**

If you discover a **high or critical severity** vulnerability, please report it
through a [GitHub Security Advisory](../../security/advisories/new) — this keeps
the details private until a fix is released. For **low severity** findings you are
comfortable disclosing publicly, open a [Security Issue](../../issues/new?template=security.yml)
on the Issues tab instead.

Include as much of the following as possible:

- A clear description of the vulnerability
- Steps to reproduce or a proof-of-concept
- The potential impact (e.g. data exposure, privilege escalation)
- Any suggested mitigations you are aware of

## Supported Versions

Only the latest release on `main` is actively maintained. Older versions do not receive security patches.

## Disclosure Policy

We follow a **coordinated disclosure** approach. Once a fix is available we will:

1. Release a patched version.
2. Publish a GitHub Security Advisory crediting the reporter (unless you prefer to remain anonymous).
